# 🛡️ EY — Technology Risk and Change-Management Controls

**Type:** EY Technology Risk Virtual Job Simulation on Forage · **Completed:** 23 October 2026  
**Status:** Independent learning simulation; not employment with EY.

## Scenario
The simulated company **Advanced Ideas Mechanics (AIM)** used a payroll application called **PayNow**. The exercise involved developing probing questions about how software changes move from request to production.

## Workflow assessed
1. HR/Payroll or IT submits a change request.
2. Changes are authorised and assigned to development.
3. Code is compiled and moved to quality assurance for user acceptance testing (UAT).
4. A Change Control Board (CCB) reviews release approval.
5. Approved changes are deployed to production.

## Risk and control questions explored
- Who can initiate and approve changes, and is authorisation documented?
- Is testing evidence retained before production deployment?
- Are development, testing and release responsibilities appropriately separated?
- What is the CCB's approval process?
- Is there a traceable record from request to production?

## Skills demonstrated
IT general controls awareness · Process mapping · Risk-based questioning · Change-management review · UAT and approval workflows

**Evidence scope:** The reviewed screenshots showed a questions list and comparison with reference material. This is a **simulation of control assessment**, not an actual IT audit, assurance engagement, or validated assessment of a live payroll system.
